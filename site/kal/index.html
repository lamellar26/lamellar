kal plate

The knowledge plate. Your own folders become a library on your machine. Before each task, the passages that matter are added to it, each with a reference to where it came from.

lamellar pack install https://github.com/lamellar26/lamellar-pack-kal
lamellar kal add ~/Documents/handbook
lamellar run "who approves leave requests?"

Needs lamellar 0.2.2 or later and git. The installer asks whether to add kal (say yes, or set LAMELLAR_KAL=1). Works offline, Python standard library only.

What it does

  • Your folders become a library. lamellar kal add <folder> splits md, txt and docx files into passages and indexes them in SQLite under ~/.lamellar/kal/. They are searchable at once. Running it again skips files that have not changed.
  • Relevant passages are added before every task. Each passage carries a [ref] to its source, and the total is capped (3,000 characters by default). Unrelated tasks get nothing added.
  • The model can look things up while it works. Two tools, kal_search and kal_read(ref), let it search the library and open a passage in full.
  • Nothing is rewritten by a model. What the model sees is your original text. Earlier versions had a model write notes from the documents; tests showed the notes added nothing, so they were removed in 0.3.0.

Measured

Documents. 30 fact questions about one book (16 chapters), 9B model, two runs each.

SetupRight, of 30
No plate12.5
kal (original passages)28.5
Model-written notes plus passages28.5, no better

With the plate, answers came in about 3 s instead of 8–20 s, and none timed out. 10 unrelated questions had nothing added.

Conversations. 20 real conversations replayed, then one follow-up question each, asked in a new session. 9B model, two runs.

SetupRight, of 20
No conversation library1 and 3
Conversation passages (default)11 and 14
Passages plus model-written notes14 and 14, but 3 of 24 notes had invented details

The rerank threshold was tuned on this same set, so a fresh set is needed for a clean number.

Conversation library off by default

Set "chat_write": true and each user gets a private library. One user never sees another user's library.

  • What is saved: what the user said and what the tools returned, after the answer is delivered. Only when a tool was used or the user stated facts; pure chat is skipped.
  • What is never saved: the assistant's own words. Passwords, keys, ID numbers, phone numbers, emails and amounts are masked before storing.
  • How it is searched: each candidate passage is scored by the model and kept only at 3 of 10 or above, so unrelated questions do not pull in long tool output.
  • Plain files are the truth: markdown under ~/.lamellar/kal/<lib>/sources/. lamellar kal rebuild rebuilds the database from it.

Commands

lamellar kal add <folder> [--lib NAME]   index a folder (or one file)
lamellar kal search "<query>"            search the libraries
lamellar kal read <ref>                  show one passage in full
lamellar kal context "<task>"           show what would be added to a task
lamellar kal status [--lib NAME]         files and passages
lamellar kal chats                       conversation libraries
lamellar kal rebuild --lib chat-...      rebuild from markdown

Settings

In ~/.lamellar/worker.json, under the key kal.

KeyDefaultMeaning
libs["default"]libraries used when answering
max_chars3000cap on added text
min_rel, rel_top0.05, 0.5relevance floor; share of the best hit to keep
rerank_model""optional reranker for all libraries
chat_writefalseconversation library on or off
chat_reranktruererank conversation passages
